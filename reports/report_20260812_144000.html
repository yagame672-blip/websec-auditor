INFO Plaintext HTTP transport CWE-319 / A02
Local demo over HTTP (development only).
TLS configuration baseline OWASP TLS Cheat Sheet source

Transport Layer Protection: all traffic must use TLS 1.2 or 1.3 with forward-secret ciphers. Disable SSLv3, TLS 1.0, and TLS 1.1. Pair this with HSTS so clients cannot be tricked into plaintext. A server negotiating below TLS 1.2 exposes data to interception.

HIGH Missing header: strict-transport-security CWE-319 / A02
Response does not include strict-transport-security.
Remediation: Add Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
OWASP Secure Headers Project OWASP Secure Headers Project source

HTTP response headers are a cheap, high-impact control. Strict-Transport-Security forces HTTPS. Content-Security-Policy limits where scripts/styles may load, blunting XSS. X-Content-Type-Options: nosniff stops MIME sniffing. X-Frame-Options (or CSP frame-ancestors) blocks clickjacking. Referrer-Policy limits what URL info leaks to third parties. A missing header is a concrete, fixable misconfiguration -- not a theoretical risk.

HIGH Missing header: content-security-policy CWE-79 / A03
Response does not include content-security-policy.
Remediation: Add a Content-Security-Policy that whitelists trusted script/style sources.
Content Security Policy (defense-in-depth for XSS) OWASP / MDN CSP source

A Content-Security-Policy is the primary browser-side defense against XSS. It declares approved sources for scripts, styles, images, and other resources; anything else is blocked. Use 'default-src https:' and avoid 'unsafe-inline'/'unsafe-eval'. CSP is defense-in-depth: it limits damage when output encoding is missed, it does not replace proper input handling.

Clickjacking defense OWASP Clickjacking Defense Cheat Sheet source

Clickjacking tricks a user into clicking a hidden element overlaid on a legitimate page. Defense: send X-Frame-Options: DENY (or SAMEORIGIN) and/or the CSP directive frame-ancestors 'none'. Without it, your authenticated UI can be framed by an attacker and used to perform unintended actions.

HIGH Missing cookie flag: Secure CWE-614 / A02
A session cookie is missing the Secure attribute.
Remediation: Set the Secure flag on all session cookies.
Session cookie hardening OWASP Session Management Cheat Sheet source

Session cookies must be protected. The Secure flag ensures they are sent only over HTTPS (CWE-614). HttpOnly blocks JavaScript access, neutralizing most XSS-based session theft (CWE-1004). SameSite=Lax or Strict reduces cross-site request forgery (CWE-1275). A session cookie missing any of these three is a real, exploitable weakness.

CWE-524: sensitive data cached by a shared or browser cache without proper control. A response that sets a session cookie but lacks Cache-Control: no-store can be replayed from cache on the same machine or a shared proxy. Send Cache-Control: no-store on every response that establishes a session.

MEDIUM Reflected input detected CWE-79 / A03
A benign probe value was echoed back UNENCODED in the response body (parameter 'q'). An attacker's script would also be echoed unencoded -> XSS surface.
Remediation: Contextual-output-encode all reflected input and deploy a Content-Security-Policy.
CWE-79 Cross-site Scripting MITRE CWE-79 source

CWE-79: Improper Neutralization of Input During Web Page Generation. Untrusted input is placed into output sent to a web browser without proper encoding, letting an attacker execute scripts in the victim's context. Reflected XSS echoes input back immediately; stored XSS persists in the application. Fix: context-aware output encoding plus a CSP; never insert raw user input into HTML/JS/attribute contexts.
